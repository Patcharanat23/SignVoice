# แก้การโบกมือและแสงน้อย

## การโบกมือ

ปัญหาจากการทดสอบคลิปโบกมือ: MediaPipe เห็น `Open_Palm` หลายเฟรม แต่คำ “สวัสดี” ไม่เกิด เพราะตัวตรวจเดิมดูเฉพาะตำแหน่งข้อมือ กำหนดให้ต้องกลับทิศ 2 ครั้ง และล้างประวัติทันทีเมื่อป้ายท่าหลุดเป็น `None` มือที่โบกโดยหมุนรอบข้อมือจึงไม่ผ่าน

แก้ใน `src/recognition.js` โดยเก็บตำแหน่ง **ปลายนิ้วกลางและข้อมือ** ในหน้าต่างเวลา 2.6 วินาที ตรวจระยะเคลื่อนและการกลับทิศ 1 ครั้ง ยอมให้ `Open_Palm` หลุดชั่วคราวไม่เกิน 550 มิลลิวินาที และล็อกคำหลังตรวจพบจนผู้ใช้หยุดแสดงฝ่ามือ โค้ดใช้ facial cue ที่พบซ้ำในช่วง 1.2 วินาทีก่อนเพิ่มคำ แทนการอ่านเฟรมเดียว

ทดสอบกับ [คลิปโบกมือ](https://huggingface.co/datasets/linoyts/wan_waving_hands/blob/main/3.mp4) เดียวกัน: **ก่อนแก้ 0 คำ; หลังแก้ “สวัสดี” 1 คำ พร้อม `smile`** ผลนี้ยืนยัน workflow ตัวอย่าง ไม่ใช่ค่าความแม่นยำกับผู้ใช้ภาษามือจริง รันซ้ำด้วย `npm run test:wave` และดู `docs/wave-test.png`

## แสงน้อย

เพิ่ม `src/image-processing.js` ให้ประมาณความสว่างจากภาพย่อ 64×36 ทุก 0.5 วินาที แล้วใช้ Canvas 2D `brightness`/`contrast` ปรับ **พิกเซลที่ส่งเข้าโมเดลทั้งมือและใบหน้า** ไม่ใช่เพียง CSS ที่แสดงผลบนจอ ค่า gain จำกัดที่ 2.2× และ UI แสดง `LIGHT` เพื่อให้รู้ว่ากำลังปรับภาพหรือควรเพิ่มไฟ

คลิปโบกมือที่ลดความสว่างด้วยซอฟต์แวร์เหลือ 25% ยังได้ “สวัสดี” พร้อม `smile` และ UI แจ้ง `มืดมาก · เพิ่มแสง 2.2×` ในการทดสอบเดียวกัน **เมื่อปิดการปรับภาพก็ยังได้คำ** จึงยังไม่มีหลักฐานว่าตัวปรับภาพเพิ่มความแม่นยำกับคลิปนี้ ต้องทดสอบกับกล้องจริงหลายระดับแสง ภาพเบลอหรือมืดจนเซนเซอร์ไม่บันทึกรายละเอียดไว้ไม่สามารถแก้ด้วยการขยายความสว่าง

การอ่านภาษามือจริงต้องฝึกโมเดลลำดับภาพที่รวมมือ แขน และใบหน้า บนข้อมูล TSL/ASL ที่มีป้ายกำกับ แล้ววัดผลกับผู้แสดงที่ไม่อยู่ในชุดฝึก ดู `docs/THAI_SIGN_DATASETS.md` สำหรับข้อมูลและ weights ที่ค้นพบ โค้ดแก้ครั้งนี้ยังเป็นตัวตรวจท่าโบกและ facial cue ของต้นแบบ
