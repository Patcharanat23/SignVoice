# คู่มือทำความเข้าใจระบบ SignVoice

> สำหรับผู้นำเสนอ อ่านเพื่อเข้าใจระบบอย่างละเอียด และตอบคำถามได้มั่นใจ
> สคริปต์ที่ใช้พูดบนเวทีอยู่ใน `SCRIPT.md` · ตัวเลขทุกตัวในไฟล์นี้วัดจริง ที่มาอยู่ใน `RESEARCH_REPORT.md` และ `docs/*.json`

## 1. ภาพรวมในหนึ่งย่อหน้า

SignVoice เป็นเว็บแอปที่รันบนเครื่องเรา ผู้ใช้ทำภาษามือไทยหน้ากล้องทีละคำ เบราว์เซอร์หาจุดของมือและแขน (ไม่ส่งภาพออกไปไหน) แล้วส่งเฉพาะตัวเลขพิกัดไปให้โมเดลที่เราเทรนเองแปลเป็นคำ คำที่ได้ถูกส่งให้ LLM ในเครื่องเรียงเป็นประโยคภาษาไทย จากนั้นเสียงสังเคราะห์พูดประโยคนั้นออกลำโพง หรือส่งเข้าไมค์เสมือนสำหรับห้องประชุม

```
กล้อง ─▶ MediaPipe Hand+Pose ─▶ ตัดช่วงท่า ─▶ SignNet (ONNX) ─▶ Qwen3 4B ─▶ ElevenLabs / ThonburianTTS ─▶ ลำโพง / ไมค์เสมือน
         [เบราว์เซอร์ GPU]       [กติกา JS]     [Python, CPU]     [Ollama]     [คลาวด์ / ในเครื่อง]
ภาพ      54 จุด × เฟรม          คลิป 1 คำ       คำ + ความมั่นใจ    ประโยค       เสียง
```

### ส่วนประกอบและที่อยู่ของโค้ด

| ส่วน | ทำหน้าที่ | ไฟล์ |
|---|---|---|
| หน้าเว็บ | กล้อง หน้าพูด หน้าจัดการท่าทาง | `index.html`, `src/main.js`, `src/signs.js`, `src/hud.js` |
| หน้าล็อกอิน / แอดมิน | สมัคร เข้าสู่ระบบ จัดการผู้ใช้ อนุมัติท่า | `login.html`, `admin.html`, `src/login.js`, `src/admin.js` |
| เซิร์ฟเวอร์ Node | ตรวจสิทธิ์ ส่งต่อคำขอ เรียก LLM และเสียง | `server.mjs`, `auth.mjs` |
| บริการ Python | รันโมเดลแปลท่า เก็บข้อมูล เทรนต่อ | `ml/service.py`, `ml/db.py`, `ml/finetune_user.py` |
| ฟีเจอร์และโมเดล | แปลงจุดเป็นฟีเจอร์ สถาปัตยกรรมโมเดล | `ml/features.py`, `ml/train_tsl.py`, `ml/train_combined.py` |

## 2. AI แต่ละตัวทำอะไร และทำไมถึงเลือก

### 2.1 MediaPipe Hand Landmarker + Pose Landmarker (lite) — หาจุด

- **ทำอะไร:** จากภาพแต่ละเฟรม หาจุดบนมือข้างละ 21 จุด (ข้อนิ้ว ปลายนิ้ว ข้อมือ) และจุดบนลำตัว (ไหล่ ศอก ข้อมือ)
- **รันที่ไหน:** ในเบราว์เซอร์ บนการ์ดจอ (WebGL) ใช้ราว 11 ms ต่อเฟรมสำหรับมือ ถ้าการ์ดจอช้ากว่า 120 ms ระบบจะสลับไปใช้ CPU เอง
- **ทำไมเลือก:**
  - เทียบกับ MediaPipe Holistic บนคลิปเดียวกัน 104 คลิป: Holistic 78.8% / 6–9 FPS, Hand + Pose **80.8% / 14–19 FPS**
  - Holistic หามือจากตำแหน่งข้อมือของ pose ก่อน ถ้าขยับเร็ว นิ้วจะหลุด ส่วน Hand Landmarker ค้นหามือทั่วทั้งภาพ
- **ไม่ใช้หน้าแล้ว:** โมเดลรุ่นปัจจุบันไม่ใช้จุดบนหน้า เพราะชุดข้อมูล TSL-ONE ไม่มีข้อมูลหน้า จึงตัดโมเดลหน้าออกเพื่อให้เร็วขึ้น

### 2.2 ตัดช่วงท่า (ไม่ใช่ AI)

`SignSegmenter` ใน `src/signs.js` เป็นกติกาธรรมดา:

| กติกา | ค่า |
|---|---|
| ลดมือลง (ไม่เห็นมือ) นานเท่านี้ = จบหนึ่งคำ | 450 ms |
| ถ้าแขนยังยกอยู่แต่มือหลุดจากการตรวจจับชั่วคราว ให้รอได้ | 1.2 วินาที |
| คลิปต้องมีเฟรมที่เห็นมืออย่างน้อย | 6 เฟรม |
| ตัดคลิปเองถ้ายาวเกิน | 4.5 วินาที |

**ท่าควบคุม** (ไม่ส่งไปแปล):
- **ยกมือเหนือหัวค้าง 1 วินาที** = พูดประโยค (ไม่มีคำในภาษามือไทยที่ทำเหนือหัว จึงไม่ชนกับคำจริง)
- **ชูสองนิ้วแล้วพับลง 2 ครั้งภายใน 2.5 วินาที** = ลบคำล่าสุด
- **ระบบฟังเฉพาะตอนหันหน้าเข้ากล้อง:** หันเข้ากล้อง 0.4 วินาทีจึงเริ่มฟัง หันไปทางอื่นเกิน 1.5 วินาทีจะหยุดฟัง กันไม่ให้ระบบจับท่าตอนผู้ใช้คุยกับคนข้าง ๆ

### 2.3 SignNet: 1D-CNN + Transformer — แปลท่าเป็นคำ (โมเดลที่เราเทรนเอง)

**ข้อมูลเข้า:** คลิปหนึ่งคำ → `prepare()` ใน `ml/features.py`:
1. ตัดเฉพาะช่วงที่เห็นมือ (`active_span`)
2. ยืดหรือหดให้ยาว **32 เฟรม** (`resample`) ทุกคำจึงยาวเท่ากัน ไม่ว่าจะทำเร็วหรือช้า
3. สร้างฟีเจอร์ **266 ค่าต่อเฟรม**:
   - ตำแหน่งจุดเทียบกับไหล่ (ยืนใกล้/ไกลกล้องได้ผลเท่ากัน)
   - รูปมือเทียบกับข้อมือของมือข้างนั้น (บอกว่ากำมือ แบมือ ชี้นิ้ว)
   - ความเร็ว: จุดขยับไปเท่าไรจากเฟรมก่อน

**โครงสร้างโมเดล** (`SignNet` ใน `ml/train_tsl.py`):
```
266 ค่า × 32 เฟรม
 → Linear 192 มิติ
 → 1D-CNN 3 ชั้น (kernel 5)       ← จับการเคลื่อนไหวช่วงสั้น ๆ เช่น นิ้วกำลังงอ
 → Transformer 2 ชั้น, 4 heads    ← ดูความสัมพันธ์ของทั้งท่า ต้นท่ากับท้ายท่า
 → ค่าเฉลี่ย + ค่าสูงสุดตามเวลา
 → ความน่าจะเป็นของ 236 คำ (กรองให้เหลือ 146 คำใช้งาน)
```
- ขนาด **0.86 ล้านพารามิเตอร์** ไฟล์ ONNX 3.3 MB รันบน CPU 0.7 ms ต่อคำ
- **ทำไม CNN + Transformer:** ภาษามือมีทั้งรายละเอียดสั้น (รูปนิ้ว) และลำดับยาว (มือเคลื่อนจากไหนไปไหน) CNN เก่งเรื่องแรก Transformer เก่งเรื่องหลัง โมเดลเล็กพอที่จะเทรนต่อในเครื่องได้ในราว 1 นาที
- **เกณฑ์ความมั่นใจ 0.35:** ต่ำกว่านี้จะไม่เพิ่มคำ แต่จะแสดงตัวเลือก 3 อันดับแรกให้ผู้ใช้กดเลือกเอง

### 2.4 Qwen3 4B Instruct (ผ่าน Ollama) — เรียงเป็นประโยค

- **ทำไมต้องมี:** ไวยากรณ์ภาษามือไทยต่างจากภาษาไทยพูด เช่น `[ข้าว, น้อง, กิน, ชอบ]` → "น้องชอบกินข้าว"
- **ตั้งค่า:** temperature 0.1 เพราะต้องการเรียงคำ ไม่ได้ต้องการความสร้างสรรค์ และจำกัดความยาวคำตอบ 120 token
- **กฎใน prompt:** ห้ามเติมคำศัพท์ใหม่ เติมได้แค่คำเชื่อมจำเป็น (กับ ที่ จะ ไหม) และถ้าเป็นการสะกดนิ้วให้รวมตัวอักษรเป็นคำ
- **ผลเทียบ 60 ประโยค** (เฉลยจากผู้จัดทำ TSL-51):

  | วิธี | เรียงคำถูก | รูปแบบที่ไม่อยู่ใน prompt | ไม่เติมคำแปลก | เวลา |
  |---|---:|---:|---:|---:|
  | ไม่ใช้ LLM | 20.0% | 28.1% | 100% | 0 |
  | Llama 3.2 3B | 46.7% | 46.9% | 90% | 0.16 วิ |
  | Gemma 3 4B | 58.3% | 59.4% | 88.3% | 0.46 วิ |
  | **Qwen3 4B** | **78.3%** | **68.8%** | 90% | 0.38 วิ |

- ถ้าไม่มี Ollama ระบบยังทำงาน โดยต่อคำตรง ๆ แล้วให้ผู้ใช้แก้ประโยคเองได้

### 2.5 เสียงพูด — ElevenLabs (หลัก) · ThonburianTTS (สำรอง)

- **ElevenLabs eleven_v3:** เสียงผู้ชาย (Brian) ล็อกค่าความนิ่งของเสียงไว้ที่ 1.0 ใช้เวลาราว 2.2 วินาที ทุกประโยคถูกเก็บแคชบนดิสก์ ประโยคเดิมพูดซ้ำได้ใน 0.007 วินาทีโดยไม่เสียเครดิต
- **ThonburianTTS (F5-TTS + Vocos):** ทำงานในเครื่อง ใช้แรมราว 2 GB จึงโหลดเฉพาะเมื่อ ElevenLabs ใช้ไม่ได้ ทำให้ปกติบริการ Python ใช้แรมแค่ราว 68 MB
- **ส่งเสียงไปที่ไหนได้บ้าง:** ลำโพง หรือไมค์เสมือน (เช่น Steam Streaming Microphone, VB-Audio Cable) ผ่าน `setSinkId` ของเบราว์เซอร์ แอปประชุมจึงได้ยินเสียงนี้แทนเสียงผู้ใช้
- **ออร่าขอบจอ:** วัดความดังของเสียงด้วย Web Audio แล้วปรับความสว่างของแสงสีรุ้งรอบจอตามจังหวะพูด

## 3. ข้อมูลและการเทรน

| ชุดข้อมูล | คำ | ผู้แสดง | ลักษณะ |
|---|---:|---:|---|
| TSL-51 (จุฬาฯ) | 51 + ท่าว่าง | 3 | landmark CSV จากวิดีโอ, มี augmentation ของผู้จัดทำ |
| TSL-ONE | 184 | 29 | landmark pose (75 จุด × 2 มิติ) |
| **รวม** | **236 → ใช้ 146** | **32** | ตัดสถานที่ ห้าง ประเทศ ชื่อกีฬา ออกตาม `ml/vocab_exclude.json` |

- **แบ่งชุดทดสอบตามคน:** TSL-ONE ผู้แสดงหมายเลข 04, 09, 15, 21, 27 และผู้แสดง `user_sign` ของ TSL-51 ไม่อยู่ในชุดเทรนเลย ถ้าแบ่งตามคลิปจะได้ 94.8–98% ซึ่งสูงเกินจริง
- **การเทรน:** AdamW, label smoothing, เพิ่มข้อมูลด้วยการเลื่อนเวลาและเติม noise ราว 10–15 นาทีบน RTX 3060 Laptop
- **รุ่นใช้งานจริง (`--deploy`):** เทรนซ้ำโดยรวมทุกคน หลังวัดผลกับคนใหม่เสร็จแล้ว

### การสอนท่าของผู้ใช้ (fine-tune ในเครื่อง)

- **ข้อมูลที่ใช้:** ท่าที่อัดหรือนำเข้า ซึ่งอนุมัติแล้ว + ข้อมูลเดิม 30 คลิปต่อคำ (กันลืมคำเดิม) + สำเนากลับซ้าย-ขวา (รองรับมือซ้าย)
- **ค่าที่ใช้:** 12 รอบ, learning rate 3e-4 คำใหม่ (`<คำ>_user`) ได้แถวใหม่ในชั้นสุดท้ายของโมเดล
- **วิธีวัดผล:** กันท่าไว้ 20% ต่อคำเพื่อวัดก่อน/หลัง ผลล่าสุด: 21 คำ, 200 ตัวอย่าง, ท่าที่กันไว้ 40 ครั้ง: **12.5% → 97.5%**
- **ข้อควรระวัง:** ท่าที่กันไว้อัดในห้อง แสง และมุมเดียวกัน จึงสูงกว่าการใช้งานในสถานที่อื่น

## 5. การเก็บข้อมูลและความปลอดภัย

### ฐานข้อมูล SQLite (`~/.signvoice/signvoice.db`)

| ตาราง | เก็บอะไร |
|---|---|
| `users`, `sessions`, `auth_log` | บัญชี, session (เก็บแค่ hash), บันทึกการเข้าใช้ |
| `words` | ชื่อคำไทย/อังกฤษ |
| `samples` | ท่าที่สอน (เก็บแค่พิกัดจุด ไม่เก็บภาพ) พร้อมสถานะ `approved` / `pending` และผู้เสนอ |
| `translations` | ทุกการแปล และคำที่ผู้ใช้กดแก้ |
| `training_runs` | ประวัติการเทรนและผลก่อน/หลัง |

**ทำไม SQLite:** ระบบรันเครื่องเดียว ไม่ต้องติดตั้งเซิร์ฟเวอร์ฐานข้อมูล เป็นไฟล์เดียว สำรองง่าย และเร็วกว่าแบบไฟล์แยกในทุกงานที่วัด ถ้าวันหนึ่งต้องรันหลายเครื่อง ย้ายไป PostgreSQL ได้ด้วย SQL ชุดเดิม

### ความปลอดภัย (รายละเอียดใน `SECURITY.md`)

- **รหัสผ่าน:** เข้ารหัส scrypt + salt ไม่มีใครเห็นรหัสจริง แม้แต่ในฐานข้อมูล
- **Session:** cookie แบบ HttpOnly + SameSite=Strict หมดอายุเมื่อไม่ใช้ 12 ชั่วโมง
- **กันการเดารหัส:** ผิด 10 ครั้งต่อ 15 นาทีต่อ IP จะถูกบล็อก ผิด 5 ครั้งติดกันล็อกบัญชี 15 นาที
- **กันเว็บอื่นส่งคำขอแทน (CSRF):** ตรวจ origin, มี Content-Security-Policy และกัน clickjacking
- **สิทธิ์:**
  - ผู้ใช้ทั่วไป: ใช้หน้าพูด และ**เสนอ**ท่าได้
  - แอดมิน: อนุมัติท่า เทรน แก้คำศัพท์ และจัดการผู้ใช้
- **ระบบเสนอท่า:** ผู้ใช้ทั่วไปส่งท่าได้ แต่ท่าจะรออนุมัติ แอดมินดูภาพเคลื่อนไหวของโครงมือก่อนกดอนุมัติ ท่าที่ยังไม่อนุมัติไม่ถูกเทรน
- **HTTPS:** ถ้าเปิดให้คนอื่นใช้ผ่าน Cloudflare Tunnel จะเป็น HTTPS อัตโนมัติ

## 6. ข้อจำกัด (พูดเองก่อนดีกว่าถูกถาม)

1. **แปลทีละคำ** ต้องลดมือระหว่างคำ ยังแปลต่อเนื่องทั้งประโยคไม่ได้
2. **ทดสอบกับคนใหม่ได้แค่ 6 คน** และยังไม่ได้ทดสอบกับผู้ใช้หูหนวกจริง
3. **ท่าคล้ายกันยังสับสน** เช่น น้า↔อา, อะไร↔ที่ไหน
4. **มือซ้ายวัดจากการกลับภาพ** ยังไม่ได้ทดสอบกับคนถนัดซ้ายจริง
5. **เสียงหลักต้องใช้เน็ต** ถ้าไม่มีเน็ตใช้เสียงในเครื่องซึ่งช้ากว่าและใช้แรมมาก
6. **เครื่อง RAM 16 GB ตึง** ถ้าเปิดโปรแกรมอื่นมาก FPS และความเร็วจะตก
7. **โมเดลส่วนตัวใช้ร่วมกันทั้งระบบ** คำที่สอนเพิ่มอาจแย่งคำตอบคำเดิม จึงต้องมีแอดมินคุม

## 7. คำถามที่อาจถูกถาม พร้อมคำตอบ

**Q: AI อยู่ตรงไหนในระบบ?**
A: 4 จุด:
- MediaPipe หาจุดมือ
- SignNet แปลท่าเป็นคำ (เราเทรนเอง)
- Qwen3 เรียงประโยค (LLM)
- ElevenLabs / ThonburianTTS สร้างเสียง

ส่วนการตัดช่วงท่าเป็นกติกาธรรมดา

**Q: ทำไมไม่ส่งวิดีโอเข้าโมเดลตรง ๆ?**
A: พิกัดจุดเล็กกว่าภาพหลายพันเท่า ไม่ขึ้นกับสีผิว เสื้อผ้า หรือพื้นหลัง โมเดลจึงเล็กพอจะรันในเครื่อง และภาพไม่ต้องออกจากเบราว์เซอร์ ซึ่งดีต่อความเป็นส่วนตัว

**Q: 86.2% วัดยังไง เชื่อได้ไหม?**
A: วัดกับผู้แสดง 5 คนที่โมเดลไม่เคยเห็นสักคลิป (แบ่งตามคน ไม่ใช่ตามคลิป) 666 คลิป ถ้าแบ่งตามคลิปจะได้ 95–98% ซึ่งเป็นตัวเลขที่สูงเกินจริง เราจึงไม่ใช้

**Q: ทำไมใช้ LLM ในเครื่อง ไม่ใช้ ChatGPT?**
A: ด้วยเหตุผล 3 ข้อ:
- เร็วกว่า (0.38 วินาที)
- ไม่มีค่าใช้จ่ายต่อครั้ง
- ข้อความไม่ต้องออกนอกเครื่อง

งานนี้เป็นการเรียงคำ ไม่ต้องใช้โมเดลใหญ่ และ Qwen3 4B ได้ผลดีที่สุดใน 3 ตัวที่ทดสอบ

**Q: ถ้าเจอคำที่ระบบไม่รู้จักทำยังไง?**
A: ความมั่นใจจะต่ำกว่า 35% ระบบไม่เพิ่มคำ แต่แสดงตัวเลือกให้กด ถ้าไม่มีคำที่ถูก ผู้ใช้สอนคำใหม่ได้ในหน้าจัดการท่าทาง (ผู้ใช้ทั่วไปเสนอ แอดมินอนุมัติ) แล้วเทรนต่อในราว 1 นาที

**Q: ใช้กับคนถนัดซ้ายได้ไหม?**
A: ได้ เดิมได้แค่ 20% เพราะข้อมูลเกือบทั้งหมดเป็นคนถนัดขวา เราเทรนด้วยท่าที่กลับซ้าย-ขวา ขึ้นเป็น 81% แต่ยังวัดจากการกลับภาพ ไม่ใช่คนถนัดซ้ายจริง

**Q: ข้อมูลส่วนตัวของผู้ใช้ปลอดภัยไหม?**
A: ปลอดภัยในระดับที่ออกแบบไว้:
- ภาพไม่ออกจากเบราว์เซอร์
- ท่าที่เก็บเป็นแค่พิกัดจุด
- รหัสผ่านเข้ารหัส scrypt

ส่วนที่ออกนอกเครื่องมีอย่างเดียว คือข้อความที่จะพูด ถูกส่งไป ElevenLabs

**Q: ทำไมเลือก SQLite ไม่ใช้ MySQL หรือ Firebase?**
A: ระบบรันเครื่องเดียว ผู้ใช้ไม่มาก SQLite ไม่ต้องติดตั้งเซิร์ฟเวอร์ ใช้ได้แม้ไม่มีเน็ต และวัดแล้วเร็วกว่าแบบไฟล์เดิม ถ้าขยายเป็นหลายเครื่องค่อยย้ายไป PostgreSQL

**Q: ถ้าเน็ตหลุดตอนเดโม?**
A: ส่วนที่ยังทำงานได้:
- แปลท่า และเรียงประโยคด้วย LLM ทำงานในเครื่องทั้งหมด
- เสียงสลับไปใช้ ThonburianTTS ในเครื่องอัตโนมัติ ช้ากว่า และครั้งแรกต้องโหลดราว 45 วินาที

**Q: ต่างจากแอปแปลภาษามืออื่นยังไง?**
A: 4 ข้อ:
- เป็นภาษามือไทย
- ประมวลผลในเครื่อง
- มี LLM เรียงไวยากรณ์ให้เป็นภาษาพูด
- ผู้ใช้สอนท่าเพิ่มเองได้ โดยมีแอดมินคุมคุณภาพ

## 8. เช็กลิสต์ก่อนเดโม

1. **ปิดโปรแกรมที่ไม่ใช้** (Discord, ChatGPT, เบราว์เซอร์อื่น) ให้ RAM ว่าง
2. เปิด PowerShell แล้วรัน:
   ```powershell
   cd <โฟลเดอร์ SignVoice>
   npm start
   ```
   ปล่อยหน้าต่างนี้เปิดทิ้งไว้
3. เปิด **Chrome หรือ Edge** (Zen/Firefox ต้องเลือกอุปกรณ์เสียงใหม่ทุกครั้ง) → `http://127.0.0.1:5173` → ล็อกอินแอดมิน
4. เปิดกล้อง แล้วดูช่อง **FRAMES** ใต้กล้อง ควรขึ้น **GPU** และ 20+ FPS
5. **อุ่นเครื่อง:** กด "พูดประโยค" หนึ่งครั้ง และให้ LLM เรียงประโยคหนึ่งครั้ง (ครั้งแรกช้า 7–9 วินาที)
6. ซ้อมคำที่จะใช้: **สวัสดี / ฉัน / ชอบ / ขอบคุณ** ทำทีละคำ ลดมือให้พ้นกล้องทุกครั้ง
7. แสงพอ ยืนให้เห็นตั้งแต่หัวถึงเอว หันหน้าเข้ากล้อง

### ถ้ามีปัญหาระหว่างเดโม

| อาการ | ทำอะไร |
|---|---|
| คำไม่ขึ้น | ลดมือให้พ้นกล้องนานขึ้น ดูว่ามีป้าย "กำลังฟัง" ไหม |
| แปลผิด | ชูสองนิ้วแล้วพับลง 2 ครั้งเพื่อลบ แล้วทำใหม่ช้า ๆ |
| ไม่มีเสียง | ดูว่าตั้ง "เสียงออก" เป็นลำโพงไหม และเน็ตต่ออยู่ไหม |
| เว็บดับ | กลับไปหน้าต่าง PowerShell แล้วรัน `npm start` ใหม่ |
| ช้ามาก | ปิดโปรแกรมอื่น แล้วรีเฟรชหน้า |
